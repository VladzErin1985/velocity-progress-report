✅ Technical Discoveries This Week

Native n8n Anthropic node has a credential bug — switched to HTTP Request node for all Claude calls (working perfectly)
GHL V1 API was deprecated Dec 31 2025 — all calls now use V2 (services.leadconnectorhq.com) with PIT token authentication
GHL requires locationId in every V2 API body or returns 403 — added to all nodes
GHL Conversations API requires "html" field for email body (not "body" or "message") — fixed in WF-VC-02
GHL auto-enables DND on contacts with repeated email bounces — must manually disable per contact in GHL settings
n8n "Using Fields Below" mode prevents Claude's special characters from breaking JSON — applied to all Claude output nodes
GHL V2 /contacts/ search by email returns 422 — redesigned WF-VC-03 to pass contactId directly in webhook payload (more reliable)
WF-VC-05: IF node requires conditions.options.version = 2 — missing this caused silent validation failure
GHL blocks duplicate emails across contacts — always use unique test emails per contact when testing workflows
Cash value from GHL custom field may include currency formatting — strip non-numeric chars with Number(String(value).replace(/[^0-9.]/g, '')) before comparison
Cross-entity handoff confirmed working: VC Policy Active → AV Investor Transition stage update + tags + Claude email + note all in one 10.7s execution
GHL Opportunities API (/opportunities/search) does NOT accept pipelineId or pipelineStageId as query params — returns 422. Must pull all by location_id then filter in Code node.
MCP tool sets header values with = prefix, causing n8n to treat API keys as JavaScript expressions — always set x-api-key and API tokens manually in UI using Fixed Value mode
MCP partial workflow update appends headers, never replaces — after any MCP header change, manually delete stale duplicate header rows in n8n UI
Anthropic /v1/messages requires both x-api-key AND anthropic-version: 2023-06-01 as Fixed Value headers — missing either returns 400/401
Claude API response text is at content[0].text — never $json.text (returns undefined). Always access via $input.item.json.content[0].text
GHL Send Email via Conversations API requires html field (not body/message) + conversationId in body — POST to /conversations/messages, not /conversations/{id}/messages
Plain text email with \n chars renders as wall of text in Gmail — convert to HTML with paragraph wrapping: split on \n\n, wrap each in <p>, replace inner \n with <br>
